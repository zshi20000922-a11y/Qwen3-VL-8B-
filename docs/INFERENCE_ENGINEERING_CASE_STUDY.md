# AI Inference 工程案例：Qwen3-VL 单卡容量与缓存分析

## 实验结论

- 在 RTX 5090 / vLLM BF16 上，冷文本多模态请求的输出吞吐从 c1 的 79.26 tok/s 增长到 c32 的 334.67 tok/s。
- c8 后吞吐接近饱和；c32 TTFT P95 达 10414.73 ms，说明继续堆并发主要增加排队，而非有效吞吐。
- 在 TTFT P95≤500 ms、TPOT P95≤30 ms 且 100% 请求达标的口径下，最大稳定档为 c2，Goodput 1.087 req/s。
- 真实追加式会话第 2 轮命中 79.30% prompt tokens，TTFT 从首轮 189.03 ms 降至 66.98 ms；随着每轮新增上下文增多，第 6 轮命中率降至 60.38%，TTFT 回升至 471.17 ms。

## 工程判断

1. 最大吞吐点不是推荐服务点；需要以业务 SLO 计算 Goodput。
2. 当前服务 `max-num-seqs=8`，c16/c32 产生明显排队；可用 admission control 将并发限制在容量范围内。
3. Prefix Cache 对追加式会话确实有效，但命中比例取决于旧前缀占总 prompt 的比例，不能用完全相同请求的 96.3% 收益代表真实聊天。
4. TPOT 在高并发下仍低于 30 ms，本次 SLO 首先由 TTFT/排队击穿，因此下一优化方向应是调度和 Prefill 隔离，而不是 Decode Kernel。

## 口径与限制

负载固定同一图片、唯一首段文本前缀和 128 个输出 tokens；图片 processor cache 可能命中。并发测试采用同步 closed-loop burst，适合寻找容量边界，但不等价于线上泊松到达流量。每档 3 批，尾延迟仍需更长时间压测后才能作为生产 SLA。
